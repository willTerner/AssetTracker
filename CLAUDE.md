## Project Overview

多币账本 (Multi-currency Asset Tracker) is a React Native (Expo) app for tracking assets in multiple currencies. It converts asset values into a configurable display currency (CNY by default), stores data in an encrypted local database, and provides add/edit/delete, daily value history, statistics, import/export, PIN protection, optional biometric unlock, and light/dark appearance settings.

## Commands

```bash
npm start              # Start Expo dev server
npm run android        # Run on Android (needs Android Studio)
npm run ios            # Run on iOS (needs macOS + Xcode)
npm run web            # Run in browser
npm run lint           # Run ESLint
npm run lint:fix       # Auto-fix ESLint issues
npm run build:android  # EAS local Android build — runs prebuild-check.sh first, requires SENTRY_AUTH_TOKEN
npm run build:test:android  # Same as above, but uses the "preview" EAS profile
npm run deploy         # Run scripts/deploy.js
```

Both `build:android` and `build:test:android` run `scripts/prebuild-check.sh` beforehand. It enforces npm as the package manager, runs `expo-doctor`, and requires `SENTRY_AUTH_TOKEN`.

### ABI split APKs

Android release builds produce two per-ABI APKs (`app-arm64-v8a-release.apk`, `app-armeabi-v7a-release.apk`) instead of one universal APK. This is driven by:

- `plugins/abiSplitPlugin.js` — appends a Gradle `splits { abi }` block during prebuild (arm64-v8a + armeabi-v7a, `universalApk false`).
- `ABI_SPLIT=true` — set in the `preview` and `production` profiles in `eas.json`. Splits are only enabled when this env var is set, so local `expo run:android` debug builds remain universal.

The generated `android/gradle.properties` currently retains all four supported ABIs (`armeabi-v7a`, `arm64-v8a`, `x86`, `x86_64`) for emulator-compatible debug builds. Since `android/` is ignored/generated, use an Expo config plugin for any persistent change to this setting.

`android/` is gitignored and regenerated by the Expo prebuild/CNG workflow. Keep persistent native build changes in `app.json` config plugins, not by editing generated files under `android/`.

## Data flow and services

- **Database** (`services/database.ts`): Opens the SQLCipher-enabled Expo SQLite database `asset-tracker-vault.db`. The database key is stored in `expo-secure-store`; encrypted values are held in the `secure_kv` table. SQLCipher is enabled by the `expo-sqlite` plugin in `app.json`.
- **Asset storage** (`services/storage.ts`): Serializes the asset list to the encrypted `@assets_v1` entry. Create generates an ID from the timestamp plus a random suffix. Update records `previousValue` only when the currency is unchanged, and sets `updatedAt`.
- **Legacy migration** (`services/migration.ts`): On first setup, migrates legacy AsyncStorage keys (`@assets_storage`, `@value_snapshots`, and the old `@app_password`) into the encrypted store, then removes the legacy keys after successful migration. AsyncStorage is retained only for this compatibility path.
- **Exchange rates** (`services/exchangeRate.ts`): Fetches CNY-based rates from `open.er-api.com/v6/latest/CNY`. Rates are cached in encrypted storage with a 24-hour freshness window. When cached rates exist, a stale refresh runs in the background; the prior rates remain available if refresh fails. Currency conversion uses the cached CNY-base rates.
- **PIN** (`services/passwordStorage.ts`): New PINs must be exactly six digits. A salted SHA-256 hash and salt are stored in `expo-secure-store`; legacy plaintext PINs are read only to verify and migrate old installs. The unlock UI displays an incorrect-attempt counter but does not currently enforce a maximum-attempt lockout.
- **Preferences** (`services/settings.ts`, `context/PreferencesContext.tsx`): Preferences are stored in the encrypted database under `@preferences_v1`. They include `themeMode` (`system`, `light`, `dark`), `defaultCurrency`, `autoLockMinutes` (5, 10, or 20), and `biometricEnabled`. Defaults are system theme, CNY, 5 minutes, and biometrics off.
- **Value history** (`services/valueHistory.ts`): Stores one `{ date, totalCNY }` snapshot per day in the encrypted `@snapshots_v1` entry. `StatisticsScreen/buildLineData.ts` filters snapshots by week/month/quarter/year/YTD/all and resamples to at most nine points.
- **Import/export** (`services/importExport.ts`): Exports JSON, CSV, and XLSX; imports JSON, CSV, XLS, and XLSX. Import merges by asset ID: existing assets are retained and only new IDs are appended. Export uses the system share sheet when available.

## Key types (`src/types/index.ts`)

- `Asset`: `id, platform, value, currency, createdAt, updatedAt?, previousValue: number | null`
- `AssetData`: `platform, value, currency` — create/update payload
- `AssetsStackParamList`: `Home` and `AssetForm` (`{ asset?, type: 'ADD'|'EDIT', defaultCurrency? }`)
- `MainTabParamList`: `AssetsTab`, `StatisticsTab`, and `SettingsTab`

`AssetForm` performs its own storage mutation and returns via navigation; it does not receive an `onSave` callback in route params.

## Design and theming

- `design/App.pen` is the current visual reference for the authentication screens, Home, AssetForm, Statistics (top/bottom frames), Settings, launch splash, and app icon. Older redesign specs under `docs/superpowers/specs/` are historical; follow the current App.pen and implemented components when they differ.
- The current App.pen screen frames use the cool neutral/blue `apple-*` tokens. Older Coral Whisper variables (`coral`, `espresso`, `honey`, etc.) remain in the file but are not used by those frames.
- Runtime semantic colors and `AppTheme` live in `src/theme/colors.ts`. `PreferencesContext` resolves the saved/system theme to `lightTheme` or `darkTheme`; use `usePreferences().theme` (or pass `AppTheme` to child components) instead of the legacy `Colors` palette in `src/constants/index.ts`.
- App.pen documents the current light appearance; the dark appearance is implemented by `src/theme/colors.ts`.

## Sentry

Initialized in `src/App.tsx` with `sendDefaultPii: false` and `enableLogs: false`; the root app is wrapped with `Sentry.wrap()`. Mobile Replay is not currently configured.

## Tooling

- **TypeScript**: Strict mode with `noImplicitAny: false`. Extends `expo/tsconfig.base`; module and module resolution are `nodenext`.
- **ESLint**: Uses `@stylistic/eslint-plugin` for semicolon and JSX indentation enforcement. Run via `eslint.config.js`.
- **Prettier**: 100-character width, single quotes, trailing commas (es5), four-space indentation, LF line endings.
- **Metro**: Sentry plugin wraps the Expo Metro config (`metro.config.js`).
- **Testing**: No app-level test framework or test script is configured yet.

## Code Style

- **Styles separation**: Keep static `StyleSheet.create()` declarations in a separate styles module, not in the component's render file. Dynamic theme/state styles may be applied in component style arrays.
- **Component organization**: Follow the feature-based structure under `src/screens/`. Use a component directory with `index.tsx` and `styles.ts` for multi-file components; small components may remain flat or share a screen-level styles module when that matches the surrounding code.
- **File length**: Keep source files at or under 200 lines. Several existing screens/services already exceed this limit; avoid expanding them and split touched logic when practical.
- **Theme colors**: Prefer semantic tokens from `AppTheme` (`src/theme/colors.ts`) for UI colors. Avoid adding new UI usage of the legacy Coral Whisper `Colors` in `src/constants/index.ts`.
- **Navigation params**: Pass `asset`, `type`, and optional `defaultCurrency` to `AssetForm`; do not pass mutation callbacks through route params.
